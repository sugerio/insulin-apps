# E-sign CI (stage A only)

The E-sign workflow runs on pull requests and main pushes changing E-sign, its workflow or shared scripts, and manually. It has read-only repository permission and no deployment job, environment or secrets. It installs from the lockfile with Node 24, checks types, runs the full suite serially (the default parallel suite has previously exhausted local loopback ports), performs local Wrangler migration checks, builds the local demo with Wrangler's **dry-run**, and builds the consolidated Worker and paired client for reserved synthetic origins. The demo build is not the deployable candidate. Neither output authorizes deployment.

The Ubuntu runner must provide `/usr/bin/google-chrome`; CI fails if it is absent. TAP results must show each named browser case and the migration test passing rather than skipped. The staged external-artifact case is intentionally opt-in and remains skipped without `ESIGN_STAGED_DIR`. Browser and runner behavior has not yet been verified in GitHub Actions. The job times out after 60 minutes; failures retain their actual output and must be investigated, not assumed to be port exhaustion. Tests use synthetic data and local fakes, not actual mail or a TSA.

The migration test uses a temporary local Wrangler state, checks a fresh ordered migration, a no-op rerun, and an invalid migration remaining failed on rerun. It does not establish upgrade safety for existing databases or prove every possible migration failure is atomic. Remote migrations require separate review and authorization. Worker rollback does not undo D1/R2 changes, sent mail or signing facts; see the deployment runbook for stop and recovery prerequisites.

The three-day CI-only artifact contains only the paired synthetic-origin candidate build, a per-file SHA-256 inventory and an archive digest. The workflow rejects links and special files and checks archive paths before uploading; no job downloads or deploys it. Anyone later extracting an artifact must independently validate member paths and types before extraction and verify both hashes; hashes do not establish provenance or deployability. No local state, `.dev.vars`, sessions or generated demo output is packaged. Do not add secrets or real data to builds or logs.

A successful local run is not proof that GitHub CI ran. The currently untracked E-sign sources, lockfile and workflow must be reviewed for public content and tracked before remote CI can cover them. No staging or production CD, cloud configuration, real email or rollout is authorized by this workflow. Independent review is still required.
